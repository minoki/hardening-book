# 処理系実装者のためのチェックリスト

実装やレビューのときに見返すためのチェックリストです。詳しい説明は各章を参照してください。

## オブジェクトファイルとリンク

- [ ] 生成するすべてのアセンブリとオブジェクトに、実行不可の`.note.GNU-stack`を付けている
- [ ] 位置独立コードを生成し、テキストリロケーションを作っていない（`-z text`でリンクできる）
- [ ] x86-64：対応しているなら`GNU_PROPERTY_X86_FEATURE_1_AND`にIBTとSHSTKを付けている
- [ ] AArch64：対応しているなら`GNU_PROPERTY_AARCH64_FEATURE_1_AND`にBTIとPAC（とGCS）を付けている
- [ ] プロパティを付けたオブジェクトは、本当にその機構に対応したコードになっている
- [ ] ランタイムの手書きアセンブリにも同じ対応をしている
- [ ] 完全RELRO（`-z relro -z now`）でリンクしている
- [ ] CIで`readelf -n`と`readelf -lW`を使い、最終成果物のELFプロパティと`GNU_STACK`を確認している
- [ ] Windows：`/guard:cf`と`/CETCOMPAT`への対応を検討した

## コード生成

### forward edge（IBT、BTI）

- [ ] 外部から見える関数とアドレスを取られる関数の先頭に`ENDBR64`か`BTI c`（または`PACIASP`）を置いている
- [ ] アドレスを取られない内部関数には置いていない
- [ ] ジャンプテーブルと計算型gotoの飛び先に`ENDBR64`（または`notrack`）か`BTI j`を置いている
- [ ] `setjmp`相当の関数の呼び出し直後と、例外のランディングパッドにlanding padを置いている
- [ ] AArch64：間接末尾呼び出しにx16かx17を使っている

### backward edge（Shadow Stack、GCS、PAC）

- [ ] `call`と`ret`を常に対にしている（`push`と`ret`による分岐や、リターンアドレスの書き換えをしていない）
- [ ] pac-ret：LRを保存する前に署名し、復元した後に検証している
- [ ] pac-ret：署名時と検証時のSPが一致している
- [ ] pac-ret：末尾呼び出しの前に検証している
- [ ] pac-ret：`.cfi_negate_ra_state`を出力している

### その他

- [ ] スタックカナリアを、Cコンパイラと同じガード値の場所を使って実装している（または実装しない理由がある）
- [ ] 大きなスタックフレームや可変長のスタック割り当てでスタックプローブを入れている
- [ ] AArch64：x18をレジスタ割り当てに使っていない
- [ ] MTEやTBIの環境で、ポインタの最上位バイトを壊すコードを生成していない

## ランタイム

### メモリ管理

- [ ] 独自アロケータにASanのポイズニングを入れている（少なくともデバッグビルドで）
- [ ] 独自アロケータを無効にして`malloc`に直接回すテスト用モードがある
- [ ] GCのスキャン関数はサニタイザの計装から外している
- [ ] ポインタの上位ビットが0だと仮定していない
- [ ] タグ付きポインタは下位ビットを使っている（上位ビットを使うなら、MTE、TBI、PACとの衝突を検討した）
- [ ] 保守的GCの「ヒープを指しているか」の判定で、タグを取り除いてから比較している
- [ ] MTEを使うなら、ヒープを`PROT_MTE`で確保し、割り当てと解放のたびにタグを付け替えている

### スタック

- [ ] スタック切り替えのコードを1ヵ所に集約している
- [ ] スタック切り替えでASanとTSanのファイバーAPIを呼んでいる
- [ ] スタック切り替えでShadow StackやGCSも切り替えている（コルーチンごとに確保している）
- [ ] 新しいコルーチンには`jmp`や`br`で入っている（偽のフレームに`ret`していない）
- [ ] 独自の非局所脱出で、Shadow StackやGCSを巻き戻し、ASanのポイズンを消し、MTEのスタックタグをクリアしている
- [ ] スタックのコピーや移動をしていない（するなら、Shadow Stack、GCS、PACとの両立方法を決めている）
- [ ] スタックを歩くコードで、リターンアドレスのPACを取り除いている
- [ ] return address hijackingを使っていない（セーフポイントのポーリングを使っている）

### JIT

- [ ] W^Xを守っている（RWXのページを作らない）
- [ ] 生成コードに`ENDBR64`や`BTI`を置き、AArch64では`PROT_BTI`を付けている
- [ ] 生成コードもpac-retの規則に従い、アンワインド情報を登録している
- [ ] arm64e：Cとやりとりする関数ポインタを署名、検証している
- [ ] Windows：CFGの有効な飛び先を登録している

## FFI

- [ ] FFIでリンクするCのライブラリがhardeningフラグ付きでビルドされている（ELFプロパティを確認した）
- [ ] Cに渡すコールバックの先頭にlanding padがある
- [ ] C側がkCFIやClang CFIを使う環境では、型ハッシュを合わせている
- [ ] クロージャのトランポリンを実行可能スタックに作っていない
- [ ] Cから受け取ったポインタの上位ビットを落としていない
- [ ] Cの`longjmp`やC++の例外が言語のフレームをまたぐ場合の挙動を決めている

## テスト

- [ ] ランタイムをASanとUBSan付きでビルドしたテストをCIで回している
- [ ] ランタイムをTSan付きでビルドしたテストを回している（並行性がある場合）
- [ ] FFI境界のテストをサニタイザ付きで回している
- [ ] QEMU（`-cpu max`）でBTI、PAC、MTEを有効にしたテストを回している
- [ ] Intel SDEや実機で、CETのShadow Stackを有効にしたテストを回している
- [ ] ランタイム、パーサ、FFI境界をファジングしている
